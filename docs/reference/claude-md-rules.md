# CLAUDE.md 運用ルール一覧

`🟢 全員`

本書は、[CLAUDE.md](../glossary.md#claudemd) に何を書き、何を書かないかの判定基準と、当チームの運用ルールを記載します。対象バージョン: v1.6 由来。

## 書くこと・書かないことの基準

| ✅ 書く(Claude が推測できないこと) | ❌ 書かない |
| --- | --- |
| ビルド・テストの bash コマンド | コードから推論できること |
| デフォルトと異なるコードスタイル | 標準的な言語規約 |
| ブランチ命名・プルリクエスト(PR)規約などリポジトリの作法 | 詳細な API ドキュメント(リンクで代替) |
| プロジェクト固有のアーキテクチャ決定 | 頻繁に変わる情報 |
| 環境の癖・よくある落とし穴 | 「きれいなコードを書け」式の決まり文句 |

判定基準は次の1文です。「その行を削除した場合、Claude がミスをするか」。しない場合、その行は不要です。肥大化した CLAUDE.md は、Claude に実際の指示を無視させます。

## 当チームの運用3原則

1. **200行以内を維持する**

   公式推奨の上限です。超えそうな場合は、[肥大化した CLAUDE.md を棚卸しする](../how-to/declutter-claude-md.md)へ進みます。強調構文(IMPORTANT / YOU MUST)は、本当に重要な1〜2個のルールにだけ使います。

2. **オーナーを1名置き、変更はプルリクエスト(PR)レビューを経る**

   オーナー不在の設定ファイルは肥大化しやすいという公式の指摘に基づく運用です。当チームでは、オーナー(AI 推進チーム担当者)の承認を必須とします。個人運用の間は、本人がオーナーです。月に1度、上記の削除基準で見直します。

3. **セッション終了時に改善提案を確認する**

   大きな作業の後、Claude 自身に「今日のセッションを振り返って、CLAUDE.md に追記・削除すべき点を提案して」と依頼し、妥当な提案を PR にします。

## 記入例:Good パターンとアンチパターン

判定基準はつねに「その行を削除した場合、Claude がミスをするか」です。

### SE向け:開発リポジトリの CLAUDE.md

#### ✅ Good パターン

```markdown
# ビルドとテスト
- ビルド: npm run build(Node 20 必須。18 では sharp のインストールが失敗する)
- テスト: npm test -- --runInBand(並列実行だと DB コンテナが競合する)

# リポジトリ作法
- ブランチ名: feature/チケット番号-概要
- PRは400行以内に分割する
- マイグレーションは必ず単独PRにする

# 落とし穴
- src/legacy/ は凍結中。修正禁止、移行チケットに起票すること
```

いずれの行も、コードを読むだけでは分からない事実です。バージョン制約・競合の理由・凍結方針は、記載がない場合、Claude が踏み抜きます。

#### ❌ アンチパターン

```markdown
# 心がけ
- きれいで読みやすいコードを書くこと
- テストはしっかり書くこと

# ファイル構成の説明
- src/utils.js は共通関数を置くファイル
- src/api/ はAPI関連のコード
  …(全ファイルの説明が80行続く)

# 重要
- 本番DBには絶対に接続するな
```

「心がけ」は行動を変えません。ファイル構成は Claude がコードから読み取れます。最後の「絶対禁止」は、CLAUDE.md への記載だけでは強制されません。[権限(permissions)](../glossary.md#権限permissions)の deny 設定や[フック](../glossary.md#フック)で実装します。

### 総務向け:文書管理リポジトリの CLAUDE.md

#### ✅ Good パターン

```markdown
# 文書の置き場所と命名
- 規程類の正本は/規程/配下のみ。改訂時は旧版を/規程/_旧版/へ移動
- ファイル名は「文書番号_名称_v版数」の形式(例: SOM-012_出張旅費規程_v3.docx)

# 取り扱いルール
- 押印済みPDFは編集禁止。修正は元のWordから作り直す
- 議事録の様式は/様式/GJ-01を使用
- 対外文書の日付は和暦で統一
```

命名規則・正本の場所・和暦統一は、ファイルを見ただけでは分からない社内の作法です。記載しておくと、Claude が文書作成・整理のたびにこれらを守ります。

#### ❌ アンチパターン

```markdown
# メモ
- みんなが分かりやすいように整理整頓を心がける

# 連絡先
- 担当: 田中さん(内線1234)
- 今月の当番: 佐藤さん

# アクセス情報
- 共有フォルダのパスワード: ******
- 社印の保管庫の暗証番号: ****
```

担当者・当番は頻繁に変わる情報のため、すぐに古くなります(台帳へのリンクが適切です)。パスワード・暗証番号の記載は、情報漏えいに直結する重大な違反です。CLAUDE.md はチーム全員と AI が読む前提のファイルのため、機密情報は書きません。

## 追記前のセルフチェック

- 削除したら Claude がミスをする内容か(No なら不要)
- 半年後も正しい情報か(No なら台帳・リンクへ)
- 「必ず/絶対」系の記述ではないか(Yes ならフック・権限設定へ)
- パスワードなどの機密を含んでいないか(含む場合は記載不可)
