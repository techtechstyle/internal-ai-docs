# コンテキスト操作コマンドと失敗パターン一覧

`🔵 SE`

本書は、コンテキスト管理に使う Claude Code のコマンドと、避けるべき典型的な失敗パターンを記載します。

## コンテキスト操作コマンド

| コマンド | 効果 | 使いどころ |
| --- | --- | --- |
| `/clear` | 会話を完全リセット | タスク切替時、修正沼にハマった時 |
| `/compact 指示文` | 指示に沿って会話を要約・圧縮 | 長い作業の途中で要点だけ残したい時 |
| `/rewind` | チェックポイントまで巻き戻す | AI の変更を取り消したい時 |
| `/cost` `/stats` | トークン使用量・コストの確認 | 使いすぎが気になる時 |

## 失敗パターン

Anthropic 公式ドキュメントが挙げる「チームに教えるべき典型的な失敗パターン」に基づく一覧です。

| 失敗パターン | 症状 | 対処 |
| --- | --- | --- |
| キッチンシンク・セッション | 1つの会話に無関係なタスクを詰め込む | タスクごとに `/clear` |
| 修正の重ね塗り | 「違う、そうじゃなくて…」を何度も繰り返す | 2回失敗したらリセットしてプロンプト改善 |
| CLAUDE.md の過剰仕様 | ルールを書きすぎて逆に無視され始める | CLAUDE.md を200行以内に保つ |
| 信頼して検証しない | 「できました」を鵜呑みにしてマージ | 検証手段(テスト)を必ずセットで与える |
| 無限探索 | 調査だけさせ続けて机が埋まる | 調査はサブエージェントに分離 |

## 結果が悪いときの切り分け順序

出力の質が期待より低いときに確認する順序です。上位の段階に問題がなければ、次の段階に進みます。

| 段階 | 確認すること | 対処 |
| --- | --- | --- |
| ① コンテキスト | プロンプトは具体的か。適切なスキルが読み込まれているか。CLAUDE.md は適切か。タスクの範囲は絞れているか | 該当箇所を見直す。問題の大半はこの段階にある |
| ② エフォート | コンテキストは十分なのに、手順を飛ばしていないか | `/effort` でエフォート(努力量)を上げる。ただし、ほとんどのタスクではデフォルトのエフォートで十分 |
| ③ モデル | コンテキストもエフォートも十分なのに失敗するか | 上位モデルに切り替える |

モデルは「どの頭脳が答えるか」、エフォートは「どれだけ粘るか」という別のツマミです。
