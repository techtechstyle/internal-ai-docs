# 既存文書を型分類して移行する

`🟢 全員` `⏱ 30分`

この手順では、既存の社内文書を4つの型に分類し、このナレッジベースへ移行します。

## はじめる前に

- 移行したい文書が手元にあること
- [執筆1ページ憲章](../_style/writing-charter.md)を読んでいること

## 手順

1. 文書全体をざっと読み、2つの質問で主となる型を決めます。

   - 読者は「学んでいる」か「作業している」か
   - 必要なのは「行動」か「知識」か

2. 型が混在している箇所に印を付けます。よくある混在は次の3つです。

   - 手順の途中にあるオプション一覧・仕様表 → reference へ切り出し
   - 手順の途中にある背景説明の長文 → explanation へ切り出し
   - 解説の中にある番号付き手順 → how-to へ切り出し

3. 主となる型のテンプレートを `_templates/` からコピーし、本文を流し込みます。切り出した部分は、それぞれの型のテンプレートで別ファイルにします。

4. 切り出した箇所には、元の位置にリンクを置きます。

   ```markdown
   その他のオプションは[リファレンス: ○○一覧](../reference/xxx.md)を参照してください。
   ```

5. frontmatter(title・type・audience・owner・review-by・freshness-class)を埋めます。owner は必ず個人名にします。

6. 型と同名のディレクトリ(`tutorials/` `how-to/` `reference/` `explanation/`)へ配置し、PR を作成します。

## 完了の確認

次の状態になっていれば完了です。

- [ ] 移行後の各ファイルが1つの型だけを含んでいる
- [ ] すべてのファイルの frontmatter が埋まっている
- [ ] 切り出した箇所へのリンクが元の位置に置かれている

この手順の操作はここまでです。分割しすぎたと感じた場合も、PR 上で相談すれば統合し直せます。

## よくあるエラーと対処

### どの型か決められない

- 原因: 文書が複数の読者状態を同時に狙っています。移行前の文書ではよくあることです。
- 対処: 「この文書を読み終えた直後に読者が何をするか」を想像してください。手を動かすなら tutorial か how-to、判断や理解に使うなら reference か explanation です。それでも迷う場合は how-to を仮置きし、PR で相談してください。

### 切り出すとファイルが小さくなりすぎる

- 原因: 1〜2段落のために独立ファイルを作ろうとしています。
- 対処: 数段落程度の補足なら切り出さず、リンク先の既存文書への追記か `> **NOTE:**` 1個で対応してください(注記は1ページ2個まで)。
