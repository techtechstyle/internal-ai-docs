# Claude Code とは — 記憶が続かない優秀なペアプログラマー

`🟢 全員`

本書では、Claude Code が何をするツールか、そしてチーム運用ルールのすべての出発点になる2つの原則について説明します。

## 結論

Claude Code は、ターミナル(黒い画面)上で動く AI 開発アシスタントです。人間に例えると「隣の席に座った、コードベース全体を読める優秀なペアプログラマー」ですが、人間と違って**記憶が続かない**という重大な特性があります。チームの運用ルールは、ほぼすべてこの特性を補うために存在します。

## Claude Code は何をするのか

エンジニアが日本語で「この機能のバグを直して」「テストを書いて」と指示すると、AI がコードを読み、修正案を作り、テストを実行して結果を報告します。指示は自然な日本語で構いません。

## 最重要原則1: コンテキストウィンドウ

Anthropic 公式ドキュメントは、ベストプラクティスの根拠を一文で説明しています。「ほとんどのベストプラクティスはひとつの制約に基づいている。Claude のコンテキストウィンドウはすぐに埋まり、埋まるにつれて性能が劣化する」。

[コンテキストウィンドウ](../glossary.md#コンテキストウィンドウ)とは、AI が一度に覚えていられる「作業机の広さ」です。会話やファイルの内容で机が散らかるほど、AI の判断力は落ちます。設定ファイルを短く保つ、タスクごとに会話をリセットする、調べ物は別の AI に任せる——チームのルールはすべて「机を広く保つ」ための工夫です。

## 最重要原則2: 記憶はセッションをまたがない

Claude はセッション(1回の会話)が終わると記憶がすべて消え、次回はまた「出社初日の新人」状態で始まります。前回教えたビルド手順も、踏んだ落とし穴も覚えていません。

この性質を補う唯一の恒久的な仕組みが [CLAUDE.md](../glossary.md#claudemd) です。リポジトリの一番上に置く1枚のテキストファイルで、Claude Code がセッション開始時に必ず自動で読み込みます。これがあると、毎回のセッションが「引き継ぎ済みの状態」からスタートします。別のメンバーの PC でも、同じノートから開始できます。だからこそ「学んだこと」は CLAUDE.md に書いて、チーム全員の資産にします。

中身のイメージは、この程度の短い箇条書きです。

```markdown
# ビルドとテスト
- ビルド: npm run build(Node 20 必須)
- テスト: npm test -- --runInBand

# リポジトリ作法
- ブランチ名: feature/チケット番号-概要
```

覚えておくポイントは3つだけです。

- 書くのは「コードを読んでも分からないこと」だけ(ビルドコマンド、規約、落とし穴)
- チーム全員のもの——git で共有し、変更は PR レビューを通す
- 短く保つ(200行以内)——長いと AI の机を圧迫し、逆に指示が無視される

## 黄金律:迷ったら /clear

前述の2原則を実践に落とし込むと、行動の指針は「迷ったら `/clear`」の一言に集約されます。当チームでは、次の2つを合言葉にします。

- 無関係なタスクに移るときは、必ず `/clear` を実行する(机の上を片付けてから次の作業へ移ります)
- 2回修正を指示しても直らないときは、`/clear` してプロンプトを書き直す

Anthropic 公式も、良いプロンプトによるクリーンなセッションは、修正が積み重なった長いセッションにほぼ常に勝ると説明しています。

### 直らないときの対応を実例で比べる

同じ「タイムゾーン変換バグが2回直らなかった」場面での対応を、良い例と悪い例で比較します。

Good パターンでは、リセットしてから仕切り直します。

```text
(2回直らなかった時点で)
/clear

日付のタイムゾーン変換バグを修正してください。
前回の試行で分かったこと:
- 原因は formatDate() ではなく API レスポンスの parse 側
- moment ではなく date-fns を使用中
完了条件: npm test date が全件パスすること
```

失敗から得た情報を最初から要約して渡し直すため、AI はきれいな机で核心から着手できます。失敗の履歴そのものは持ち越しません。

一方、アンチパターンは修正を重ね塗りします。

```text
違う、そこじゃない
→ いや、だからタイムゾーンの話
→ さっき直したところ元に戻ってるよ
→ もう一回最初から見直して
→ なんで別のファイルを触っているの
```

会話には失敗した試行と矛盾する指示が積み重なり、AI はその散らかった机ごと参照し続けます。回を追うごとに精度が下がる悪循環に陥り、時間とトークンを浪費します。

実際に使うコマンドの一覧は[コンテキスト操作コマンドと失敗パターン一覧](../reference/context-commands.md)を参照してください。

## 基本の仕組み(イメージ)

以降の文書で繰り返し登場する仕組みです。今は「例え」でイメージだけつかめば十分です。正確な定義は[用語集](../glossary.md)にあります。

| 仕組み | ひとことで言うと | 例えると |
| --- | --- | --- |
| セッション | 1回の会話。終わると記憶が消える | その日限りの打ち合わせ |
| plan モード | コードを「読むだけ」で編集しない安全なモード | 工事前の現地見学 |
| スキル | 関係する作業のときだけ AI が読む手順書 | 棚のマニュアル |
| サブエージェント | 調査やレビューを任せる別働隊の AI | 別室のアシスタント |
| フック | 決まったタイミングで必ず動く自動処理 | 工場の安全装置 |
| 権限(permissions) | AI に許す操作・禁じる操作のリスト | 入退室カードの権限設定 |
| サンドボックス | AI の実行コマンドを隔離する安全な箱 | 公園の砂場 |
| MCP | 外部サービスと AI をつなぐ接続規格 | コンセントの規格 |

## もうひとつの原則: 「お願い」と「強制」の違い

Claude Code への指示は、効き方の異なる2種類に分かれます。

| 種類 | 具体例 | 効き方 | 使いどころ |
| --- | --- | --- | --- |
| 助言的(お願い) | CLAUDE.md、ルールファイルの指示 | AI は従おうとするが、長い作業中や攻撃的な入力で見落とすことがある | 破られても事故にならないこと(規約・手順) |
| 決定論的(強制) | フック、権限設定、managed settings | プログラムが機械的にブロックするため必ず効く | 絶対に破られてはいけないこと(「.env を読むな」「sudo 禁止」) |

> **WARNING:** 「絶対にやってはいけないこと」を CLAUDE.md への記述だけで済ませることは禁止します。Anthropic 公式も「プレッシャー下、長いセッション中、プロンプトインジェクションによって失敗しうる」と明言しています。必ず権限設定・フックで強制してください。

## 環境の全体像

準備するものは大きく3点です。役割は兼務でも構いません(例: ベテラン SE が AI 推進チームを兼ねる)。

| 準備するもの | 担当 |
| --- | --- |
| ① メンバーの PC(Claude Code 本体+サンドボックス+個人設定) | 各メンバー |
| ② リポジトリの共有資産(CLAUDE.md・`.claude/` 一式・`.mcp.json`) | ベテラン SE / AI 推進チーム(個人運用では本人) |
| ③ Claude のプラン契約・アカウント・台帳 | 総務 |
| ④ 任意: GitHub Actions 自動レビュー・MCP 外部連携 | AI 推進チーム |

②のリポジトリが「共有資産の正本」であり、clone するだけで全員が同じ環境になります。個人運用の間は「メンバー1名+自分のリポジトリ」に縮小した同じ形で準備します。

## 設定を「チームの資産」としてコミットする理由

CLAUDE.md や `.claude/` 配下の設定は、個人の PC に溜め込まず、リポジトリにコミットしてチームの資産にします。Anthropic 公式も、CLAUDE.md を git にチェックインしてチームが貢献できるようにすることで、価値が時間とともに複利的に増えていくと説明しています。

秘伝のタレのように個人の PC だけに設定を溜めると、異動や退職で知見が失われます。コードと同じくプルリクエスト(PR)でレビューする運用にすれば、設定自体もチームで改善していけます。具体的な構成は[共有設定ファイルの構成と優先順位](../reference/shared-config-structure.md)を参照してください。

## 新人研修での活用

Anthropic 自身のデータインフラチームは、新メンバーがコードベースを探索する標準手順として Claude Code を使っています。従来のデータカタログを置き換えたと報告しています。当社も同じ方式を採用し、新メンバーのオンボーディングに組み込みます。最初の一歩は[はじめての Claude Code](../tutorials/get-started-with-claude-code.md)で体験できます。
