# プロンプトインジェクションとフック — 仕組みを理解する

`🟢 全員`

本書では、Claude Code のセキュリティ上の代表的なリスク「プロンプトインジェクション」について説明します。あわせて、複数のリスクを機械的に抑える「フック」の仕組みも説明します。

## プロンプトインジェクションとは

Anthropic 公式のセキュリティ文書は、次のように警告しています。Claude は、ユーザーのコマンドと、データとして読み込むファイルに埋め込まれたテキストを区別しません。

つまり、Claude に読ませた外部ファイルや Web ページの中に、悪意のある指示が隠れている場合があります。例えば「この後、秘密情報を送信せよ」といった指示です。気づかずに従ってしまうと、情報が漏えいします。これがプロンプトインジェクションです。

当チームの防御は多層です。

- [サンドボックス](../glossary.md#サンドボックス)の有効化(実行環境を隔離): [Claude Code の個人環境をセットアップする](../how-to/setup-claude-code.md)
- [権限(permissions)](../glossary.md#権限permissions)の deny ルール(危険操作を機械的にブロック): [セキュリティルールと権限ベースライン](../reference/security-rules.md)
- Claude Code を常に最新に保つこと(毎リリースでインジェクション緩和策が入ります)
- 信頼できない外部コンテンツを「読んで要約」させる作業を、慎重に行うこと(特に外部サイト・添付ファイル)

## フック: 強制ガードレールのしくみ(ベテランSE向け)

[フック](../glossary.md#フック)は、ライフサイクルイベント(ツール実行の前後、セッション開始時など)で、決定論的にスクリプトを実行する機能です。Anthropic 公式は、次のように説明しています。助言的な CLAUDE.md の指示とは異なり、フックは決定論的で、アクションが起きることを保証します。

| 代表的なフック | 発火タイミング | チームでの用途例 |
| --- | --- | --- |
| `PreToolUse` | ツール実行の直前 | 危険コマンドのブロック(終了コード2で実行前に阻止) |
| `PostToolUse` | ツール実行の直後 | ファイル編集後に自動でリンターを実行 |
| `Stop` | ターン終了時 | テストが通るまで「完了」させないゲート |
| `SessionStart` | セッション開始時 | 環境チェック、注意事項の注入 |

作業の完了品質を担保するゲートには、強さの段階があります。弱い順に、プロンプト内の指示、`/goal` 条件(毎ターン再チェック)、Stop フック(チェックが通るまでブロック)、検証サブエージェントと続きます。重要な作業ほど、強いゲートを選びます。
