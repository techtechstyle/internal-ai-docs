# textlint と一緒に文書を書く

`🟢 全員` `⏱ 20分` `📶 初級`

このチュートリアルを終えると、textlint の指摘を読み、自分で文章を直せるようになります。VS Code の波線と、ターミナルでの一括チェックの、両方の使い方を体験します。

## はじめる前に

**必要なもの**

- textlint をセットアップ済みの VS Code([VS Code で textlint を有効にする](../how-to/setup-textlint-vscode.md)を先に完了していること)

**前提知識**

- ターミナルの基本操作(コマンドを実行できる程度)

## ステップ1: わざと違反を書いて、指摘を見る

1. `docs/tutorials/practice.md` という練習用ファイルを作り、次の一文を書いて保存します。

   ```text
   これは、とても、長くて、分かりにくい、確認用の一文です。
   ```

   出力は一例です。表現は実行のたびに変わりますが、一文の下に波線が表示され、カーソルを合わせると次のような表示が出ます。

   ```text
   一つの文で"、"を4つ以上使用しています ja-technical-writing/max-ten
   ```

   次の要素が含まれていれば成功です。

   - [ ] 該当の一文に波線が表示される
   - [ ] カーソルを合わせると、ルール名(`max-ten`)が確認できる

2. 読点を減らして、一文を2つに分けます。

   ```text
   これは、とても長くて分かりにくい一文です。確認用に書きました。
   ```

   保存すると、波線が消えます。

## ステップ2: 別の指摘を試す

もう一度、今度は別の種類の違反を試してみましょう。

1. 練習用ファイルに、次の一文を追記します。

   ```text
   このやり方で、たぶん、うまくいくと思います。
   ```

   出力は一例です。表現は実行のたびに変わりますが、次のような表示が出ます。

   ```text
   弱い表現: "思います" が使われています。 ja-technical-writing/ja-no-weak-phrase
   ```

   次の要素が含まれていれば成功です。

   - [ ] 波線が表示される
   - [ ] `〜と思います` のような、断定を避ける表現が原因だと分かる

2. `思います` を削除するか、事実として書き直し、波線が消えることを確認します。

## ステップ3: ターミナルでまとめてチェックする

練習用ファイルを残したまま、リポジトリ全体をチェックしてみましょう。

1. ターミナルで次を実行します。

   ```bash
   npm run lint:text
   ```

   出力は一例です。表現は実行のたびに変わりますが、次のような結果が返ります。

   ```text
   docs/tutorials/practice.md
     3:1  error  ...(直前に確認した内容と同種のエラー)
   ✖ 1 problem (1 error, 0 warnings, 0 infos)
   ```

   次の要素が含まれていれば成功です。

   - [ ] 練習用ファイルのエラーが一覧で表示される
   - [ ] 他の `docs/` 配下のファイルにはエラーが出ない

2. 練習用ファイルを削除し、もう一度実行します。

   ```bash
   rm docs/tutorials/practice.md
   npm run lint:text
   ```

## 完了の確認

ターミナルで次を実行します。

```bash
npm run lint:text
```

次の状態になっていれば完了です。

- [ ] コマンドがエラー0件で終了する
- [ ] VS Code の編集中に、ルール違反箇所へ波線が表示されることを確認済み
- [ ] 練習用ファイル(`practice.md`)は削除済み

## できたことの振り返り

このチュートリアルでは、次のことができるようになりました。

- VS Code の波線とホバー表示で、書きながらリアルタイムに指摘を確認する
- 読点過多・弱い表現など、複数の種類のルール違反を見分ける
- `npm run lint:text` で、リポジトリ全体をまとめてチェックする

次は、実際の文書を書くときに[執筆1ページ憲章](../_style/writing-charter.md)を見ながら進めてください。読めない指摘が出た場合は、[スタイルガイド](../_style/style-guide.md)で該当ルールを調べます。

## よくあるエラーと対処

### `npm run lint:text` が実行できない

- 原因: リポジトリのルートで実行していないか、`npm install` が未実行です。
- 対処: リポジトリのルートに移動し、`npm install` を実行してから、再度実行します。

### 直したのに波線が消えない

- 原因: ファイルが保存されていません。
- 対処: ファイルを保存(Ctrl/Cmd + S)してから確認します。
